纯前端 · 零依赖 六页线上运行 内核已对拍验证 移动端适配 行情源为非官方接口

1　项目概述

1.1　背景

本项目的起点是一条 Python 分析脚本链（第 12 / 14 / 15 号脚本），能按缠论口径算出一类买点，但存在三个硬伤：

  • 哪里都跑不了——依赖 Python 环境与 talib、matplotlib，只能在本机命令行运行，无法在手机上随手看；
  • 结果不可交互——输出的是静态图片，不能缩放、不能切周期、不能追问"这个中枢在哪"；
  • 口径会漂移——同一套算法被复制到多个页面后各自演化，出现"同一只票两处中枢不一样"。

同时，此前已有一个挂在 GitHub Pages 上的旧版分析页，算法是启发式的（用"最近 20 日涨跌"猜中枢方向、找不到就退化成分位数箱体），且主数据源在新浪 json_v2.php——该接口没有 CORS 头，一上公网就取不到数，线上页面实际是废的。

1.2　产品定位

一句话定位

把已对拍验证过的缠论算法内核，做成打开即用、口径统一、可分享的纯前端分析站点——不装环境、不连服务器、一个链接就能看。

1.3　目标用户与使用场景

用户场景诉求
本人（主用户）
兼职量化交易者		 盘中/盘后看某只票的结构；收盘后扫一遍自选股有没有一买 快速、口径可信、能在手机上打开
同事 / 朋友 收到一个链接，想看某只票 不需要注册、不需要装东西，改代码就能查
自己（学习态） 对照缠论原文（108 课）验证算法实现是否符合定义 算法口径可追溯、可与旧版对照

1.4　设计原则

原则含义落地方式
口径唯一同一套算法只在一处维护，其余页靠构建注入内核 chan-core 只在走势分析台维护，其余页由 build.py 注入，发布前校验哈希一致
顺序不可跳分型→笔→中枢→走势→背驰→买卖点，不可倒推内核固定计算链；页面只消费结果，不做二次推断
数据源可活公网页面只能用浏览器能直连的接口只用带 ACAO 的腾讯接口或 JSONP，见 §5
零依赖部署不引入打包器、框架、CDN单文件 HTML，含内联 CSS/JS/favicon，GitHub Pages 直接托管
判断可追溯每个结论都要能说出依据页面展示闸门通过情况、中枢清单、笔序、MACD 力度对比

4　算法规格

顺序铁律（不可跳步、不可倒推）
1 分型→2 笔→3 线段→ 4 中枢→5 走势类型→6 背驰→7 买卖点

历史上曾因跳步导致 5 分钟级别分析全线出错，此后固化为强制顺序。

4.1　各环节规则

环节实现依据要点
K 线包含处理缠论原文按方向取高低点极值合并，消除包含关系
分型缠论原文顶/底分型三根 K 线判定，再作分型序列筛选
笔第 69 课 + 12/14/15 号脚本画笔规则 + 笔过滤（不满足过滤的笔不成笔）
线段第 67 / 71 课特征序列法
中枢第 18 课连续三笔重叠区间，取 ZD ~ ZG。禁止用统计分位数或涨跌幅方向猜中枢
走势段第 17 课起按中枢关系划分上涨/下跌/盘整
一买第 15 号脚本九闸门下跌 + 盘整 + 下跌走完 → 一类买点
背驰MACD 力度比较同向相邻两笔的 MACD 柱面积/力度衰减，且创新极端价

5　数据源规格

5.1　接口清单

用途接口跨域复权状态
日 / 周 / 月 K 线 web.ifzq.gtimg.cn/appstock/app/fqkline/get ✅ ACAO: *前复权（qfq）主源
5/15/30/60 分 money.finance.sina.com.cn/.../jsonp.php ✅ JSONP 免跨域疑似不复权主源
行情名称 qt.gtimg.cn/q= ✅ ACAO: *—在用
兜底 K 线 push2his.eastmoney.com —前复权已被 IP 限流

5.2　数据源铁律

公网纯前端页面只能这样取数
  • ✅ 响应头带 Access-Control-Allow-Origin 的接口（腾讯系）
  • ✅ JSONP 回调方式（新浪分时）
  • ❌ 无 CORS 头的普通 JSON 接口 —— 新浪 json_v2.php 就是这一类，公网必挂
  • ❌ 已被限流的东财 push2his（本机 IP 实测全灭）
  • ❌ 依赖第三方 CORS 代理（allorigins 等）—— 不稳定且会泄露请求

本地 file:// 打开时不校验 Origin，看不出问题；必须用线上 URL 实渲染才能验证取数是否真的通。

5.3　周期与窗口参数

周期参数窗口备注
5 / 15 / 30 / 60 分m5 / m15 / m30 / m60480 根跨多日时 X 轴显示日期，单日显示时间
日线d800 自然日—
周线w240 根由日线聚合
月线mo180 根由日线聚合

统一规则：未走完的当前周期 K 线保留并参与计算（v4.9 起，2026-09-22 修订）。
缠论判的就是当下，未走完的 K 线正是当下的载体；而笔的成立仍要求分型已确认， 未确认的部分不会被当成完成的笔，无需在数据层提前砍掉。页面对进行中的末根标注「本周 / 本月进行中」 （lastBarLive()，仅标注、不做任何截断）。
原规则「未走完的当前周期 K 线一律丢弃」已取消 —— 它会让 9-22 打开周线时停在上周五 9-18， 本周整根消失，走势停在过去，看不见当下。

5.4　降级与容错

  • 腾讯源失败 → 回落东财兜底（虽已限流，但在其他网络环境下仍可能可用）
  • 批量扫描：单只失败不中断整批，失败行标注原因
  • 页面显示本次实际使用的源，便于判断数据可信度

11.2　术语表

术语含义
分型三根 K 线构成的顶/底转折形态，是笔的基本构件
笔连接相邻顶底分型的线段，需满足笔规则与笔过滤
线段至少三笔构成，用特征序列法判定结束
中枢连续三笔重叠的价格区间，记作 ZD（下沿）~ ZG（上沿）
一买一类买点：下跌 + 盘整 + 下跌走完的位置
二买二类买点：活动一买（九道闸门过且至今未跌破）后回抽不破一买低点的位置（无活动一买不判）
三买三类买点：突破中枢 ZG 后回抽不跌回中枢的位置
背驰同向两段走势力度衰减（系统用 MACD 柱力度量化）
chan-core本项目算法内核脚本块，唯一维护点为走势分析台
chan-ext内核扩展块：二买/三买/背驰量化/位置导航
ZD / ZG中枢下沿 / 中枢上沿
